# 附录 J 按模块走读（供复现与答辩委员翻代码）

本附录仍不增加新贡献。它按仓库包把「打开这个文件你该看见什么」写成讲义，方便把论文句子对到代码。路径相对于仓库根目录。

## J.1 world-spec：说明书本体

`packages/world-spec/src/schema.ts` 里是 Zod 模式：向量、风格锚点、区域、门、实体、身份、子区域、物体、关系、条件、效果、规则、任务、呈现。读它时请带着四个栏目：空间、主体、结构、因果。呈现字段再往后放。`genreProfile.ts` 里三个体裁包和 `evaluateEmergenceGate`。闸门逻辑只有几行：窗口到了且扩散率不够则失败。不要在这里寻找复杂统计。`toGameSeed.ts` 的注释写明确定性、无时钟无随机。测试 `toGameSeed.test.ts` 有字节级一致用例，答辩可现场跑。

## J.2 world-ops：改建许可证

`ops.ts` 的判别联合列出全部算子。读 `applyWorldOp` 时跟踪三件事：失败是否保持原世界、版本是否加一、脏资产键是否合理。合并世界的前缀是命名空间。把区域挂到起始区域的双向门，是为了减少孤岛。测试应覆盖失败不变与成功留痕。

## J.3 world-sim：法律的火

`simulator.ts` 的 `evalCondition` 与 `applyEffect` 是小解释器。读的时候写几个真值表：缺省标志、背包成员、任务状态机。日程移动不传送的注释是对呈现层寻路的尊重。可玩性探针在同包，用规则能不能推进来回答「这世界至少不是摆设」。

## J.4 world-planner：合同编译器

`intent.ts` 是抽出。把经典小镇正则和否定正则对照着读，能理解「不要广场」为什么不是广场请求。`synthesize.ts` 是无模型时的世界工厂，禁名逻辑在标识生成函数里。`planner.ts` 是出路 A/B/C。`agentic.ts` 是飞行员与导演。`ensureDepth.ts` 分社会补人和角色扮演补压力。`locale/` 下文案池决定中英和体裁串味与否。测试文件是贡献二的证据柜。

## J.5 world-agents：日子

`tick.ts` 很长，建议按步进顺序列一个提纲贴在显示器上。`societyWorldModel.ts` 很短，建议打印出来当创新点三的物证。`needs.ts` 的阈值 0.72 和上升速率是设计选择。`beliefs.ts` 的事实键与传闻前缀决定传播测量会不会被同义句打散。`retrieval.ts` 标明 Park 公式。`plan.ts` 的节拍目录决定无模型时多样性从哪来。`eval/metrics.ts` 与 `eval/harness.ts` 标明评测卡是闸门。`agents.test.ts` 的用例名可直接做成幻灯片目录。

## J.6 world-neural 与 world-runtime

`hybrid.ts` 的想象循环有快照与恢复，读的时候确认没有把预测写回规约。难度提案字段名必须与编译旋钮一致，否则 L2「有用」只是日志。`spatial/` 下 LingBot 相关文件的注释重复「不拥有玩法」。边车在 `services/lingbot-sidecar`。许可证在文档里，不在权重二进制里自动出现，人必须读。

## J.7 平台流水线

`apps/platform-worker/src/worldPipeline.ts` 的 `runWorldGenerateJob` 是工序正文。`worldQualityGate.ts` 是合同执行器。`societyHeartbeat.ts` 与 `societyRunner.ts` 是日子的在线与快跑。`talkScheduler.ts` 与定住有关。Web 侧 `apps/platform-web/src/components/World/` 是观察者界面，「为什么条」是否真的展示了驱动原因，决定第 6 章的可解释性是不是只写在论文里。

## J.8 建议的本地阅读下午

第一小时：规约测试。第二小时：规划器测试，专门看渔村与空间站。第三小时：智能体测试，专门看预算耗尽仍交谈、职业不同日程、驱动打断。第四小时：打开流水线函数，对照第 8 章清单。不要一上来就跑视频边车。

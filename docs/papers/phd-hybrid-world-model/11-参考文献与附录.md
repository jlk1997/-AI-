## 11.2 附录 A 算法伪代码

### 算法 1 承诺约束的世界生成

```
输入: 提示词 p, 预算 B
输出: 世界规约 W 或失败

I ← ParseIntent(p)          // 体裁, 地点, 职业, 人口, 禁名
若 允许模型且 B 未尽:
    W_raw ← LLM_WorldJSON(p, I)
    W_raw ← Soften(W_raw)
    若 Valid(W_raw) 且 W_raw ⊨ I:
        W ← W_raw; 来源 ← llm
    否则
        W ← Synthesize(I, p); 来源 ← heuristic_merged 或 heuristic
否则
    W ← HeuristicOrSynthesize(I, p); 来源 ← heuristic
W ← EnsureDepth(W, I)
W ← FulfillPromises(W, I)
若 非 QualityGate(W, I): 进入修复环(上限 N)
若 仍失败: 返回失败
W.presentation.plannerSource ← 来源
返回 W
```

### 算法 2 社会步进（含占用惊讶）

```
输入: 社会状态 H, 步长 dt, 预算参数 θ
输出: 更新后的 H 与本步事件

H.simTime ← H.simTime + dt
s ← OccupancyModel.observe(H)
若 s ≥ 0.12:
    对每个居民 a: 抬高 a.needs.curiosity
对每个居民 a:
    AdvanceNeeds(a, dt)
    若 Urgent(a) 且 距上次驱动重规划足够远:
        Replan(a); 记录驱动原因
EnsureDayPlans(H, θ.planBudget)
对每个居民 a:
    perc ← Perceive(a, H)
    r ← DecideReaction(a, perc, θ)
    若 r = converse: 进入对话候选
    若 r = investigate: 走向异常/物体
    否则 StepLocomotion(a)          // A*, 先走到门
UseOrInvestigateObjects(H)
Talks ← ScheduleTalks(H, θ.talkCap, θ.llmTalkCap)
对每个 talk:
    若 有模型额度: LLM对话 或 定住等待
    否则 模板节拍
    SpreadImportantMemories(talk)
    RememberTold(信念)
FlushEmbeddings(H)
MaybeReflect(H, 阈值 150)
返回 H
```

### 算法 3 混合想象与难度提案

```
输入: 规约 W, 权重 φ 或空, 候选动作集合 A
输出: 排序后的想象结果; 或空的难度提案

若 φ 为空: 返回空提案
snapshot ← W
对每个 a ∈ A:
    恢复 snapshot
    pred ← MLP_φ(encode(W), encode(a))
    在 Sim 中执行 a 对应效果
    actual ← encode(Sim.world)
    surprise(a) ← ||pred - actual||_2
恢复 snapshot
按 surprise 升序排列
mean ← 平均有限惊讶
confidence ← 1 / (1 + mean)
pressure ← 由敌人密度与生命比估计
tunables ← Mix(confidence, pressure, 默认旋钮)
返回 tunables
```

### 算法 4 涌现门禁

```
输入: 轨迹 τ, 种子文本 s, 体裁 Γ
输出: pass 或 fail

card ← BuildReportCard(τ, s)
gate ← EvaluateEmergence(运行小时, card.spread, Γ)
若 gate.windowReached 且 非 gate.spreadOk: fail
若 card.scheduleDiversity 或 novelty 低于实现阈值: fail
否则 pass
```

## 11.8 附录 H 给非本专业读者的系统通识讲义

本附录不引入新贡献。它用更慢的速度把正文再讲一遍，供跨专业评委、策划、工程师和家人阅读。若你已读懂第 1 章和第 6 章，可以跳过。若你觉得正文仍然像在说行话，请从这里开始。

### H.1 三个厨房比喻

第一个厨房：厨师每次做菜都即兴写一本新的菜谱软件。软件能跑，菜有时好吃。你问「这道菜有没有放你答应过的香菜」，厨师说「你尝尝不就知道了」。这是只生成游戏代码、不保留世界说明书的厨房。

第二个厨房：墙上循环播放高清炒菜视频。看起来热气腾腾。你伸手去拿锅铲，拿到的是屏幕。这是只有视频世界、没有可执行事实的厨房。

第三个厨房：墙上有固定的菜单合同，后厨按合同备料，服务员按合同上菜，电视里可以放宣传片。宣传片里的菜再好看，也不能把菜单上的「不含香菜」改成含香菜。这是本文的厨房。

### H.2 用户到底买的是什么

用户以为自己买的是「一座会动的小镇」。真正交到手里、并且应该能退货检验的，是四样东西。样一：一张能勾选的清单，上面写着有哪些地方、哪些人、什么制度。样二：一部能快进的日子，快进之后能问「这件事传开了没有」。样三：一个能点进去走两步的画面。样四：一份改动记录，写着上次「再加一个厨子」是怎么改进去的。缺任何一样，退货时都会吵起来。系统论文的任务，就是让这四样东西有各自的模块，并且模块之间谁听谁的事先说清。

### H.3 从一句话到清单

「运河货船，八个人，舰桥，休眠舱，不要广场。」这句话在人听来是整体。在机器里必须拆。制度：值班，不是农历。人数：八。地点：舰桥、休眠舱。禁令：广场。拆完之后生成器才允许开工。生成器若仍产出广场，质检员必须打回，而不是说「广场也挺像聚集地的」。像不像由用户后来评价；允不允许由合同现在决定。这两个判断混在一起，质检员就会心软，心软就会塌模板。

### H.4 清单如何变成日子

清单上的人还不会饿。日子模块给每个人一本日记（记忆）、一张今日行程（计划）、四个内在压力（饿累社交好奇）、一双脚（寻路）、一张嘴（对话）。时间按一刻钟往前拨。拨一次，人走一步，也许说一句话，也许因为全船人的分布和预测不一样而心里痒，决定去看一眼。把二十四小时拨完，质检员数一数：那件种子事情有几个人的日记里出现了；傍晚有没有挤在同一块地方；是不是所有人走了同一条路线。数得出来，才叫活。数不出来，只叫生成了很多字。

### H.5 预测为什么要进心跳

天气预报若只印在学术期刊上，不会有人带伞。人流预测若只停在离线训练脚本里，不会有人改变下午。本文把一种很简单的预测放进每一拍：刚才人挤在哪，刚才猜人会挤在哪，两者差多少。差得多，大家更想去看。这不是因为简单预测比大模型更聪明，而是因为它在场。在场的傻瓜预测，比不在场的天才预测，更像世界模型这个词在生活里的意思。

### H.6 画面为什么可以挂掉

宣传片服务器可以宕机。宕机之后，菜单还在，后厨还在，日子还能快进。若宣传片宕机导致后厨停工，说明你把宣传片当成了菜单。分层的全部意义在这一次宕机里见分晓。论文里写 L3 可缺席，不是谦虚，是验收标准。

### H.7 模型没钱了会怎样

对话模型按次计费。二十五个人每一步都深度交谈，账单会先于剧情结束。所以每一步只允许若干次真正的模型调用。其余的交谈用模板把重要消息塞进对方日记。模板不文学，但文学不是门禁。门禁问的是知不知道。不知道还假装在深入交流，才是对观察者的欺骗。系统在没新闻时选择闭嘴，比编一句「今天天气不错」更像人，也更像诚实的机器。

### H.8 编辑为什么不能当聊天记录覆盖

用户说「再加一个厨子」。若系统把整座船重新生成，旧的谣言、旧的走位、旧的修订号全部消失。观察者会以为自己在跟一个失忆的神说话。正确做法是开一张改建许可证：新增一个实体，挂到休眠舱，连上关系，留下版本号。许可证可能被拒绝，例如新厨子的家写成了 `home_row`。拒绝比覆盖健康。

### H.9 什么叫塌模板，用生活再说一次

你去裁缝店说要一件水手服。裁缝给你一件旗袍，因为旗袍是店里的镇店之宝，所有学徒第一件都会做。旗袍很精致。它仍是错的。斯坦福小镇就是很多生成系统的旗袍。禁名表是店规：没有点名要旗袍，不准从仓库把旗袍偷出来改两个纽扣冒充水手服。

### H.10 什么叫涌现，用生活再说一次

班里有人知道了考试提前。一天后如果只有同桌知道，这叫没传开。如果全班都知道，这叫传开。你不能靠班长写一篇「消息迅速传遍全班」的作文来证明传开。你要去抽问。抽问就是评测卡。规定「一天后至少七成知道」就是门禁。把门禁写进产品，等于规定：作文不算数。

### H.11 本文创新用家长能懂的四句话

第一句：先写说明书再做游戏。  
第二句：把孩子的愿望写成可打勾的清单，生成得不对就打回。  
第三句：让小镇里的人会因为「人怎么和我想的不一样」而自己改变下午。  
第四句：电影再好看，也不能改考试成绩册。

### H.12 本文诚实用家长能懂的四句话

第一句：我们没有发明人怎么记忆这件事，前人已经做过会过日子的居民。  
第二句：我们没有训出能替代说明书的超级大脑。  
第三句：我们还没有请很多真人来打分，所以不能说「玩家更喜欢」。  
第四句：Nature 杂志大概不会登做游戏系统的文章，我们会把内容拆去游戏人工智能的期刊和会议。

### H.14 一条虚构但合法的十二小时故事

早上八点，八名船员按班次出现在舰桥和货舱。占用模型还什么都不懂，惊讶为零。九点，耳语进入机工的日记：今晚交班改到货舱。十点，机工在走廊遇见水手，额度还在，模型写了两句抱怨。水手日记出现「听同伴说」。信念记下机工已经告诉过水手。十一点，模型额度用尽。水手遇见值班官，模板仍把消息拷过去。十二点，好奇还不高。十三点，货舱人异常地多，惊讶超过阈值，值班官放下舰桥上的例行检查去看。十四点，观察者在画面上看到三个人停在货舱门口。十五点，评测卡上的知晓人数变成三。还没到窗口，门禁不审判。若一直停在三人，十二小时窗口到了，船员包的五成线（八人中要四人）可能失败。失败是有用的：它告诉你传播血管还太细，或者种子写得太难被转述。系统论文欢迎这种失败。演示论文害怕这种失败。本文选择前者。

## 11.9 附录 I 设想中的答辩问答（答案保持诚实）

问：你的方法和 Park 2023 的本质区别是什么？  
答：认知循环继承他们。区别是世界从提示词编译而来并受合同否决，制度可换包，占用预测在心跳里改变行为，涌现是回归门禁，游戏由规约编译且视频不能改账本。

问：占用模型这么简单，凭什么算创新？  
答：创新不在预测器的容量，在耦合：残差进入需求，需求进入可观察移动。没有耦合的复杂预测器对下午没有影响。请看实验清单第二条，做完才能说耦合改变了评测卡。现在只能说耦合已实现并有阈值。

问：为什么没有用户实验还写博士论文？  
答：系统贡献可以先以可运行实现和回归测试存在。学位是否接受，由学校决定。本文已把用户实验列为必须补的项，并拒绝用空数字占位。

问：正则抽地点也算方法吗？  
答：抽出本身不是贡献。抽出结果拥有否决权、与禁名和体裁绑定，才是贡献。若换成大模型抽出，否决权应保留。

问：L2 的多层感知机是否太弱？  
答：弱是故意的。它证明接口：同一轨迹格式可换 RSSM。弱模型能改难度旋钮，说明旋钮不依赖吹嘘。观察世界跳过它，说明体裁意识。

问：如何避免开源被用于操纵舆论仿真？  
答：默认定位是游戏观察玩具。干预写日志。若用于人群研究应走伦理审查。论文第 10 章写了这条。不能靠技术彻底阻止滥用，只能不在宣传里假装居民是人。

问：和 OpenGame 那篇 arXiv 是不是一回事？  
答：不是。那篇是游戏代码智能体。本文是世界栈。共享基础设施，不共享第一创新点。

问：你如何证明没有塌模板？  
答：规划器测试里有渔村、夜市、空间站、否定广场等多条用例。我不能证明对所有中文句子都不塌。我能证明已知塌法被钉住，并且门禁对脚手架标识失败。

问：涌现百分之七十达到了吗？  
答：这是产品阈值，不是本章报告的测量均值。单元测试在短窗口无模型条件下使用更松的百分之三十。请不要把阈值写成成绩。

问：最大的弱点是什么？  
答：对照实验未做；意图抽出仍浅；占用模型会滞后；L3 常为模拟帧。弱点写在第 9、10 章，不在致谢里用「未来更美好」带过。

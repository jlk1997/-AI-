# 第8章 编译流水线与质量门禁

## 8.1 大白话导读：工厂的工序比口号重要

前面几章像车间里的机床：规约、合成、社会、想象、布景。没有工序，机床会互相踩脚。先画画后校验，会得到精美的错世界。先让导演开疆再检查承诺，会得到热情的塌模板。先训练 L2 再发现这是观察小镇，会得到无用的敌人旋钮。

本章按真实任务写工序：生成、编辑、训练、社会快跑、心跳。然后写门禁。门禁是工厂的质检员，不是市场部海报。

## 8.2 世界生成任务的工序

用户在 Web 切换到世界模式，发送提示词。接口入队 `world_generate`。工作进程 `runWorldGenerateJob` 大致如下。

**规划。** 调用 `planWorldFromPrompt`。密钥耗尽则失败并说明，不静默降级。发出规划事件，带上来源、区域数、实体数。

**结构校验。** 无效则抛错。有效世界继续。

**呈现戳记。** 根据提示词或环境决定二维、三维、是否 LingBot。社会观察默认不开电影层。叙事种子写入。若项目简报有画风而规约没有，拷过来；反过来也可以写回简报。

**可选编排。** 开关打开时跑飞行员与导演，应用合法算子。

**深度与承诺。** `ensureWorldDepth` 按社会或角色扮演补人/区或补任务/敌人。`fulfillSocietyPromises` 再补地点与职业空洞。

**内容门禁。** 失败则进入修复迭代，上限默认三轮。修复提示包含失败摘要。仍失败则任务失败。成功才允许资产。

**符号预热。** 模拟器步进零或若干，让规则和日程落到稳定初值。

**可选 L2。** 非观察小镇时可采集、训练或加载权重，提案难度旋钮写进呈现提示。

**持久化。** 世界头、修订、从规约抽出的项目记忆写入数据库。

**工作区。** 生成无逻辑的呈现脚手架；写出 `world.json`、`gameplay.json`、风格锚点；跑资产生成；从 ASCII 锻造瓦片；需要时写 L3 海报。

**L3 再检。** 该有可播槽位的区域必须可探测。社会小镇或小世界要求每区都有；更大的角色扮演世界至少要起点和前沿。

**构建与发布。** 安装依赖、打包、上传、登记预览。构建前写入社会回放文件，以免清空目录把它洗掉。

**社会播种。** 从规约水合居民，准备心跳。

每一步都向事件流发人类可读摘要。前端时间线不是装饰，是工序的可观察性。没有它，失败会变成「模型不好」这种无法行动的归因。

## 8.3 从规约到游戏种子

编译器把区域变成场景，把实体变成带标签和行为的种子对象，把传送门变成切换，把任务变成对话与胜负条件的素材，把风格锚点变成资产说明书。模式版本写入种子，运行时按 1.x 校验。

确定性要求禁止读时钟、禁止掷骰。同一规约两次编译应字节级一致（在序列化稳定的前提下）。这让缓存、测试和谱系有意义。若编译器为「看起来不那么死」而加随机，测试将无法区分回归和运气。

社会观察世界的种子仍可生成可走的场景，但玩法清单以观察、对话、推进时间为主，而不是战斗循环。角色扮演世界才把追击、生命、接触伤害等旋钮放进去。L2 提案只在后者有意义。

呈现脚手架刻意不含玩法逻辑。逻辑在引擎解释器里。智能体或程序员若把胜负写死在某个场景文件，就绕过了编译器，也绕过了门禁。流水线无法在数学上禁止这种绕过，代码规范与评审必须补上。学术上，我们把「解释器执行规约」定为正确实现，把「场景私藏规则」定为缺陷。

## 8.4 编辑、训练与双轨生成

编辑任务读用户自然语言，规划成算子列表，逐个应用，再走校验与门禁。理解失败不得报成功。脏资产键触发局部重绘而不是全盘否定。谱系增加一笔。预览重新挂载。社会同步策略决定重启日子还是补人进旧日子。

训练任务采集轨迹、训练网络、存权重。可以同步，可以入队。它不改规约，只改 L2 建议器。

游戏生成仍走另一条有限状态机：规划、资产、编码、构建、内容质检、修复。两条轨道共享工作进程和存储，不共享认知循环。控制台用模式开关把用户放上正确的轨道。把世界提示丢进游戏代码智能体，会得到一局也许能玩的游戏，但没有可修订的世界对象；反过来，把「做一个贪吃蛇」丢进世界合成器，会得到奇怪的小镇。意图分类属于平台责任，本文不展开分类器细节，只要求：世界轨道必须显式进入。

## 8.5 社会快跑与心跳

快跑接口把社会推进若干小时，写入记忆、姿态、事件和评测卡，导出回放。用于评测和「快进到傍晚」。心跳接口在有观察者时按步推进，处理对话调度和定住，通过订阅通道通知前端。租约避免多工作进程打同一座镇，也避免无人观看时烧额度。

回放文件是事件的电影，不是第二份规约。播放器应按事件移动角色，而不是按自己的人工智能再演一遍。再演一遍会失去可复现性。观察者干预插入新事件后，从光标重算后续。

## 8.6 质量门禁清单

把门禁写成清单，是为了让威胁模型可操作。

**结构门禁。** 类型、引用、起始区域、门的两端。

**承诺门禁。** 地点、职业、人口、禁名、体裁区间。

**深度门禁。** 社会人不够则失败或先填充再检；角色扮演缺少压力则失败。

**可玩探针。** 在符号模拟器上尝试推进，看任务是否能被开始或完成，或至少规则能点火。社会模式不要求任务完成。

**资产诚实。** 需要真图时，探测缓冲区是否像 PNG 而不是占位。

**L3 槽位。** 需要电影层时，地址必须可播。

**谱系门禁。** 编辑不得无记录地换掉世界身份。

**涌现门禁。** 快跑之后评测卡过闸。窗口未到不误杀。

**构建门禁。** 打包失败则修复或失败，不发布半截站点。

内容门禁在资产之前，L3 门禁在资产之后。两次检查不是重复：第一次拒绝错世界，第二次拒绝错皮肤。

修复循环有上限。上限是承认模型不是神。无限修复会把任务变成无限账单。失败必须留下日志。诚实的失败比假装的小镇有价值。

## 8.7 可观测性与计费边界

事件流按角色与阶段记录。规划、质检、构建、失败各有摘要。这对于研究同样重要：来源标记、修复轮次、门禁失败原因，是第 9 章能写「不是编的」的前提。

额度与密钥轮换发生在社会对话客户端。401 一类错误轮换，而不是改写世界。思考标签被剥掉。截断的 JSON 被尝试修复。这些是模型供应商现实，不是算法贡献，但它们决定降级路径会不会被误触发。

## 8.8 工序如何落实不变量

不变量 1（网经不改账本）：L2 只写难度提案字段；L3 只写空间资产字段；任务字段只经算子或效果修改。

不变量 2（降级仍传播）：社会步进的对话上限可以大于模型对话上限，差额走模板。

不变量 3（编辑留谱系）：每次 `Apply` 写修订。

不变量 4（先质检后画画）：资产阶段在内容门禁之后。

不变量 5（编排经算子）：飞行员导演出口是 `WorldOp`。

若未来有人加入「让模型直接改 `world.json` 字符串」的快捷方式，应视为架构回归。

## 8.9 修复提示应当长什么样

把「校验失败」四个字丢回模型，模型会重写整个世界，承诺可能更糟。修复提示应包含：失败条目列表、当前区域名与居民职业摘要、禁名表、用户原句。它应要求最小修改。最小修改与世界算子是同一哲学在提示词里的投影。若修复轮次里每次都换标题换体裁，谱系会变成噪声。测试难以覆盖「提示词写得好不好」，但可以覆盖「失败后是否仍禁止脚手架」。后者比文笔重要。

## 8.10 工作区与对象存储

生成物落在项目工作区，构建产物上传对象存储，预览用签名地址。社会回放必须在清空目录的构建之前写入 public。这个细节不学术，但它决定观察者打开预览时看不看得到日子。论文写它，是因为可玩混合世界模型若只存在于数据库、不存在于预览，对用户等于不存在。系统贡献包含「最后一公里」。最后一公里经常被方法论文省略，然后在开源复制时全部失败。

## 8.11 双轨控制台的认知负荷

同一输入框既生成贪吃蛇又生成货船，用户会输错轨。模式开关、地球图标、双轨引导是产品细节，也是方法细节：意图分类错误会让整条管道的评价失真。论文要求世界轨道显式进入，等于把分类错误从方法误差里剔除。若未来做自动分类，必须单独报告分类准确率，不能把分错轨的失败算到合成头上。

## 8.12 门禁的顺序不可交换

先资产后门禁：精美错误。先 L3 后内容：影片绑定错误地理。先涌现后结构：在非法世界上测传播。先编译后校验：种子固化幻觉。唯一合法的早门禁是结构与承诺，唯一合法的晚门禁是皮肤与构建。涌现在社会快跑之后，可在预览前或后，但必须基于合格规约。顺序是架构，不是风格。

## 8.13 小结

流水线把生成、编辑、训练、生活和呈现排成不会互相踩脚的工序。门禁把幻觉、不可玩和塌模板变成可失败的检查。下一章只用这些检查和仓库里已有的测试说话，并列出还没做、因此不能写进结论的实验。

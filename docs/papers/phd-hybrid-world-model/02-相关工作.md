# 第2章 相关工作与理论基础

## 2.1 大白话导读：前人已经把路挖到哪了

写相关工作不是为了证明「我读过很多论文」，而是为了避免把别人的里程碑说成自己刚修的桥。这一章按问题来组织，不按会议年份堆砌。每个方向先讲它解决了什么，再讲它把什么留给了本文。

读者如果只记住一张表，请记住表 2-1。

**表 2-1 本文与主要相关方向的对照（大白话版）**

| 方向 | 它最擅长 | 它通常不保证 | 本文如何接住 |
|------|----------|----------------|--------------|
| 程序内容生成 | 多样的地图、规则、关卡 | 用户那句话被当成合同 | 承诺约束合成 + 质量门禁 |
| 潜空间/视频世界模型 | 预测下一步观感或帧 | 背包和任务的可复现因果 | L2/L3 不得改 L1 |
| 生成式智能体 | 记忆、计划、八卦传播 | 世界从提示词新长出来 | 内核接到 Spec 上，并加上在线占用模型 |
| 游戏 DSL / 运行时 | 稳定玩法骨架 | 过日子的社会 | 规约编译成种子，社会另走心跳 |
| 游戏代码智能体 | 从提示词到能跑的游戏 | 世界作为可修订对象 | 对照而非主贡献 |

## 2.2 程序内容生成：多样性很强，合同感很弱

程序内容生成是游戏研究里最老也最扎实的传统之一。Togelius 等人把 PCG 描述为用算法生成游戏内容，并区分在线/离线、必要/可选、确定性/随机等维度。实践中，噪声函数长地形，语法和图文法长地牢，搜索和进化算法优化可玩性，基于规则的系统长任务。Wave Function Collapse 一类方法让局部图案长成全局贴图，看起来像魔法，本质仍是约束传播。

这条传统给本文留下两笔遗产。第一笔是：**世界应该被生成，而不是只被手摆。** 第二笔是：**生成必须能谈约束。** 好的 PCG 从不是纯随机，而是在可玩性、连通性、风格一致性上接受检查。

它留下的缺口同样清楚。经典 PCG 的输入通常是参数和随机种子，不是一句含地点承诺、人口承诺和制度承诺的中文。即便近年用大模型来驱动 PCG，常见模式仍是「模型写描述，再交给旧生成器」或「模型直接写内容」。前者容易丢失提示词里的专有地点，后者容易失去可检查性。更关键的是，PCG 很少同时要求：生成结果既是社会模拟的舞台，又是游戏编译器的输入，又必须能用差分算子修订。

本文不试图用 Perlin 噪声长一座山。仓库里甚至没有生物群系气候模型。我们生成的是符号化的区域、传送门、居民身份和 ASCII 可行走布局。这在 PCG 分类里更接近**约束驱动的结构化内容生成**，而不是高度图生成。承认这一点，是为了不把本文伪装成图形学地形论文。

## 2.3 世界模型：会想象下一步，不一定会记账

「世界模型」这个词在不同社区里不是同一个东西。

在强化学习里，世界模型通常指智能体内部对「若采取动作 \(a\)，状态会变成什么」的预测器。Ha 与 Schmidhuber 的 World Models 用变分自编码器压画面，用循环网络想未来，用控制器在想象里训练。Dreamer 系列把这个想法做到能在多种控制任务上学习。这里的科学问题是样本效率和规划。世界是向量，不是剧本。

在表示学习里，JEPA 一类方法强调预测潜空间而不是像素。它关心的是可迁移的预测结构。对游戏产品而言，潜空间预测仍然不是任务状态机。

在生成式媒体里，Genie、Oasis 以及一批交互视频模型把「世界」理解成可步进的帧序列。LingBot-World 把动作条件化的视频和飞行员/导演式编排推到可演示的程度。视觉冲击力极强。问题是：帧不是背包。你无法在不另建一套符号状态的前提下，断言「矿石已交付、任务已完成、这场对话已经发生过」。许可证与算力还把这类模型关在研究或非商用的房间里。

本文采用一个看起来保守、对可玩系统却激进的立场：**预测模型可以存在，但账本必须另写。** L2 的小型多层感知机或可替换的 RSSM 负责想象；L3 的视频后端负责好看；L1 的规约负责真假。这不是因为我们轻视世界模型，恰恰是因为我们认真对待了它的能力边界。一个会做梦的人仍然需要户口本。

与经典世界模型论文相比，本文还有一个位置上的差别。强化学习世界模型通常服务于「同一个智能体把任务做得更好」。本文的在线占用模型服务于「一群居民要不要改变今天下午」。预测对象不是像素，而是「人在哪些区域」。误差不是拿去更新策略梯度，而是拿去抬高好奇心。第 6 章会把它写成算法。这里只需标明：它继承了世界模型「预测下一步」的精神，但接到了生成式社会的驱动器上。

## 2.4 生成式智能体：会过日子，世界往往是现成的

Park 等人 2023 年的 Generative Agents 是本章最需要敬重的工作。他们证明：给智能体一条记忆流，用近因、重要性和相关性检索，在重要性累积到阈值时反思，按天做计划，再根据感知决定是否打断自己，一群人就能在沙盒里表现出可识别的社会行为。谣言传播、关系形成、晚会协调，这些评测至今仍是「活」的黄金尺子。

本文社会内核明确站在这条传统上。记忆种类、检索公式、反思指针、日计划，都能在 `packages/world-agents` 里看到对应实现。我们不把这些写成「本文首次提出」。

Park 工作默认的舞台是作者构建的 Smallville。智能体很强，世界生成很弱。把它产品化会立刻遇到 Park 论文可以不写的问题：

1. 用户的世界不是 Smallville。船员值班和修道院日课的时间制度不同，社交窗口不同，人口上下限不同。一套写死的广场逻辑会在货船上变得荒谬。
2. 大模型很贵。二十五个人每一步都完整走一遍计划、反思、对话，账单会先于社会死亡。必须有预算和降级，而且降级不能停掉谣言。
3. 「活」如果只存在于演示视频里，回归测试无法抓住它。必须把传播率、聚会、多样性写成会失败的门禁。
4. 智能体若不会因为「人群去了不该去的地方」而感到惊讶，他们的好奇就只是日程表上的装饰。
5. 干预（对某个人耳语）若总从模拟零点重放，观察者会看到时光倒流。产品需要从回放光标接着算。

这些不是对 Park 的批评，是把实验室智能体接到可生成世界上时必然冒出来的系统科学问题。本文第 6 章的增量全部围绕这些问题，而不是围绕「再实现一遍记忆流」。

后续还有 AI Town、各种多人角色扮演演示、以及把生成式智能体塞进 Minecraft 的工作（Voyager、MineDojo 等更偏开放世界技能获取）。它们证明了工具使用和探索。本文舞台不是方块世界生存，而是可观察的生活制度，并要求同一份世界能被编译成网页游戏。评价标准因此不同：我们看八卦有没有传开，不看钻石有没有挖到。

## 2.5 神经符号与「单一真相源」

神经符号计算试图让神经网络的柔软和符号系统的可检查性住在同一所房子里。实践形态很多：神经网络提出候选，符号系统做验证；符号结构提供骨架，网络填充参数；两者在不同时间尺度上合作。

游戏领域其实早就有朴素的神经符号：行为树是符号，动画是连续的；任务状态是符号，寻路是几何的。出问题的时刻，几乎总是有人让连续模块去改符号事实——例如用生成模型的一句对白直接把任务标记为完成，而不经过条件检查。

本文把神经符号立场写死成架构不变量：**L1 永不被神经网络替换。** 这句听起来像工程口号，它其实是可证伪的科学主张。如果某次实验表明，关掉符号模拟器、只留下视频预测，任务完成判定仍然稳定可复现，那么本文的分层就被证伪了。我们尚未看到这样的证据，也不假装已经做了那次实验。我们看到的是相反的工程事实：一旦视频或大模型胡话进入任务状态机，回放和门禁立即失效。

「单一真相源」（Single Source of Truth, SSOT）来自软件工程，不是人工智能术语。把它用到世界上，意思是：区域名字、居民职业、任务条件和时间，只允许有一份权威拷贝。呈现层可以有很多皮肤，权威拷贝只能有一份。World Spec 承担这个角色。WorldOp 保证修改也打在这份拷贝上，而不是打在某个 Phaser 场景的局部变量上。

## 2.6 游戏运行时、DSL 与内容编译

游戏引擎研究提供了另一条线索：玩法应当被描述，而不是每次从空白发明。ECS（实体-组件-系统）、场景图、行为树、脚本 DSL，都在降低「同一类游戏每次生成一条全新代码路径」的风险。OpenGame 平台里的 `@opengame/runtime` 把少量稳定接口（场景、实体、行为、技能链、DSL）暴露给代码智能体，正是这个动机。

本文世界栈与运行时 DSL 的关系是编译关系，不是替代关系。`compileWorldToGameSeed` 把区域变成场景，把实体变成带行为的种子对象，把传送门变成切换，把风格锚点变成资产生成说明书。编译必须确定性：同一份规约，不允许因为时钟或随机数得到另一份种子。这个要求在 PCG 里叫做可复现，在编译器里叫做参照透明的一个弱版本。

设计编译器（GDD 文本抽物品和任务）是相邻工作。它处理的是「设计文档 → 系统表」，不是「世界规约 → 社会 + 游戏」。叙事修复（在再次花费大模型去修故事门之前，先用确定性规则把章节图变合法）说明同一哲学：能不用模型的一致性问题，就不要用模型碰运气。

对话模块也要分清。脚本对话管理器按图行走，适合战斗循环里的固定对白。社会对话是另一条路：检索记忆、可能调用大模型、扩散谣言、写下信念。两者可以出现在同一产品里，但不要混成一个「AI 对话」名词。

## 2.7 从提示词到游戏的代码智能体

大模型作为程序员，已经从补全函数走到了多文件智能体。游戏比普通软件更难，因为实时循环、资源管线和跨文件状态会把局部正确的代码变成不可玩的整体。OpenGame 用 Game Skill（模板技能与调试技能）、特化代码模型和面向构建健康、视觉可用、意图对齐的评测来攻击这个问题。这是严肃工作，也是本文的项目邻居。

邻居不等于本文。代码智能体优化的是一局游戏能否交付。世界栈优化的是一个世界能否作为对象被生成、校验、模拟、修订、观察。一个成功的游戏生成可以没有居民心跳；一个成功的世界生成可以暂时用色块呈现。把两篇文章写成一篇「我们什么都做了」，对审稿人和答辩委员都不公平。

平台里仍然存在共享基础设施：同一套 Worker、对象存储、密钥和 Web 控制台。游戏生成走 PLAN–ASSET–CODE–BUILD–QA–FIX；世界生成走 planWorldFromPrompt–校验–门禁–脚手架–社会心跳。第 8 章会画这张双轨图。相关工作层面只需说明：RAG、项目简报和会话记忆属于代码智能体侧的上下文工程，社会记忆流属于世界侧的认知架构，名字都叫 memory，不是同一个模块。

## 2.8 多智能体社会仿真的更老传统

在生成式智能体之前，计算社会科学和多智能体仿真已经用规则智能体研究过隔离、舆论和流行病。Sugarscape、NetLogo 模型、基于方程的流行病模型，都不需要大语言模型。它们的优点是可分析、可重复；缺点是台词和个性很薄。

本文站在中间。社会步进本身是确定性随机种子下的规则循环，大模型只在预算允许时写计划、写对话、写反思。关掉模型，模板对话和启发式计划仍能让门禁有意义地失败或通过。这个设计让我们能把「语言模型带来的文学性」和「仿真带来的可重复性」分开讨论。许多演示做不到这一点：一关模型，社会就变成哑巴空城。

信息传播研究给了涌现门禁一个外部标准。流行病学里的基本再生数、谣言模型里的知晓比例，都在问同一类问题：一条消息在网络上走多远。Park 用约七成居民在约一天内知情作为观察性标准。我们把它写进体裁包：小镇 0.7/24 小时，船员 0.5/12 小时，修道院 0.6/18 小时。阈值不同，是因为制度不同，不是因为我们随意改数字好看。

## 2.9 评测：从「能不能跑」到「算不算活」

游戏人工智能评测长期困在代理指标上。代码能否编译，帧率是否稳定，关卡是否可解，这些必要但不充分。OpenGame-Bench 把无头浏览器和视觉模型引入游戏生成评测，是对「可玩性比静态代码难验证」的直接回应。

世界评测还要更麻烦。一个世界可以构建成功，却没有人把消息传开；可以截图很美，却所有人走同一条日程；可以对话很多，却在重复同一句。因此本文把评测分成三层，而不是一个分数。

- **结构层：** 规约校验、承诺覆盖、禁止脚手架编号。
- **可玩层：** 探针能否推进任务或至少存在可观察循环；呈现能否构建。
- **涌现层：** 传播、关系、聚会、多样性、新颖度。

第 9 章不会假装这三层已经变成一个排行榜。排行榜需要固定题集和多人重复实验。我们现在拥有的是可运行的门禁和可复现的模拟器。对博士论文而言，先把指标定义清楚，比先报一个无法复核的百分比更重要。

## 2.10 相邻系统的更细对照

除了经典论文，还有一类「看起来像本文」的产品与开源演示，答辩时几乎一定会被问到。

各类 AI Town 演示把多个人设丢进同一聊天室或同一张 2D 地图。它们证明了对话调度和简单移动。它们通常没有体裁包，没有禁名，没有把涌现写成持续集成失败，也没有把同一世界编译成带任务权威的游戏。缺的不是热情，是合同与账本。

各类「LLM 地下城主人」把模型当作地下城的神。神可以很会讲。神也可以忘记你已经失去左臂。规约与模拟器存在的理由，就是把神降职为编剧顾问。顾问可以提议算子，神职被撤销。

各类关卡图生成器（包括基于学习的 PCGML）能从现有关卡学习分布再采样。它们解决「这一类关卡还要更多」。用户句子里的专有地点不是分布里的样本，是这次合同里的条款。用分布去覆盖条款，就会生成很像训练关卡、很不像用户要的船。

各类故事生成器能写出情节节拍。节拍若不住在标志位和任务状态上，社会层的谣言和故事层的主线会打架：居民在传播一个永远不会进入任务系统的秘密，或任务完成了居民却无人知晓。本文把叙事栏目放进规约，把谣言放进记忆流，并要求写回必须过桥。故事生成器可以在节拍层工作，但应输出效果列表，而不是输出一段无法执行的散文。

## 2.11 评测传统里还缺哪一格

游戏人工智能教材会教竞赛、代理、内容生成评测。人机交互会教游戏体验问卷。多智能体会议会教合作效率。生成式智能体论文贡献了传播、关系和晚会。仍然缺一格：**提示词合同的兑现率。**

兑现率不是 BLEU，不是「模型自己觉得好」。它是：地点出现了吗，职业出现了吗，人数对吗，禁名消失了吗，制度文案有没有串味。这一格之所以缺，是因为以前的生成器不以一句话为输入，或以一句话为输入却把评价交给人类看一眼截图。截图看不出 `home_row` 还在不在。标识符检查比截图更不浪漫，也更难作弊。

本文把这一格补上，并不声称它取代可玩性和涌现。三层评测必须同时在，因为三层威胁会组合。只测兑现率，可能得到可核对但死寂的世界。只测涌现，可能得到很会八卦的错误星球。只测构建，可能得到空壳游戏。

## 2.13 程序内容生成再展开：搜索、语法、学习

搜索式 PCG 把内容生成看成在巨大空间里找满足约束的点。进化算法、模拟退火、蒙特卡洛树搜索都用过。优点是约束明确时可证明「至少满足这些」。缺点是适应度函数一旦包含「像不像用户那句话」，就又把不可微的语言判断塞回去。本文不在关卡空间里做进化，而在规约空间里做生成加否决。否决比适应度硬：不满足承诺就是 0，不是 0.3。

语法式 PCG 用形状语法或图文法保证局部合法。ASCII 布局的字符规则是一种极简语法：边是墙，内部要有路。它不试图表达建筑风格史。它只表达可走。把语法做大，可以长出更漂亮的船。那是图形学增量，不是本文主贡献。主贡献是：语法的结果仍要挂上用户的地名，而不是生成完美却匿名的舱。

学习式 PCG（PCGML）从既有内容学分布。它在「更多类似内容」上强，在「第一次出现的专有承诺」上弱。夜市若从未出现在训练集，模型会抽最近的镇。禁名表是对分布先验的对抗装置。对抗先验听起来消极，对合同却是必要的。任何学习式合成若要接入本文管道，必须接受同一否决权，否则只是把塌模板从规则塌成了统计塌。

## 2.14 生成式智能体之后发生了什么

Park 之后出现了大量复现、加速和游戏化。有人把记忆换成向量数据库，有人把计划换成工具调用，有人把小镇换成办公室或狼人杀。模式大多是：换舞台、换模型、加工具。较少有人把「舞台从哪来」当成一等公民。更少有人把传播率写成会让持续集成变红的断言。

加速工作很重要。完整认知循环很贵。本文用预算和模板降级走另一条加速路：不是蒸馏一个更小的端到端智能体，而是允许循环缺模型时仍是循环。蒸馏可以成为未来工作。现在先保证缺模型时社会不是空城。

把生成式智能体用于非玩家角色战斗配合，属于另一评测：击杀、协作、冷却。本文评测是过日子。不要用战斗 NPC 论文的指标来要求观察小镇，也不要用晚会指标去要求射击游戏。体裁包就是为了阻止这种指标串味。

## 2.16 世界模型文献的层次，避免把词用混

第一层是控制与强化学习里的世界模型。它们把环境当成可在潜空间里滚动的动力学，目标是少试错、多规划。评价是累积奖励和样本效率。本文的 L2 想象属于这一层的远亲：同样比较「预测下一状态」和「真实下一状态」，但不拿它训练控制器去通关，只拿惊讶拧旋钮或排序动作。

第二层是表示学习里的预测。JEPA 一类强调不要预测像素本身。本文同意「不要让像素当账本」，但没有训练 JEPA。引用它们是为了说明：预测可以不对着像素，也可以不对着任务标志。

第三层是生成媒体里的交互视频。评价是帧质量、动作可控制、时长。本文 L3 属于这一层的插件。插件的评价是可缺席、不改任务、许可证可分离。把第三层的指标拿来评价第一层或社会层，会得到「我们的小镇没有 4K」这种无意义判决。

第四层是本文的占用模型：预测的是人流分布，评价是它有没有改变可观察行为。这一层在经典综述里几乎没有名字。没有名字不是因为高深，是因为以前世界模型很少接到生成式社会的需求上。给它起名「在线占用世界模型」是为了不再和另外三层抢同一个词。

## 2.15 本文位置：不是新名词，是新接法

如果用最短的学术句子描述本文位置：

> 本文把程序内容生成的约束思想、软件工程的单一真相源、生成式智能体的认知循环、以及世界模型的预测精神，接到一个以符号世界规约为账本、以社会心跳过日子、以游戏引擎为皮肤的混合系统上，并让涌现成为可失败的产品门禁。

新名词可以取「可玩混合世界模型」或「承诺约束的生活世界编译」。它们只是标签。审稿人真正要看的是：哪些模块是继承，哪些接法是新的，哪些数字是测出来的，哪些数字是代码里写死的阈值。第 3 章开始，我们把标签换成符号。

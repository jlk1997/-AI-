# 第4章 世界规约与世界算子

## 4.1 大白话导读：户口本比小说重要

编剧喜欢写小说。引擎喜欢写场景。用户喜欢看动画。这三样东西都能撒谎。户口本不太会撒谎——不是因为它高尚，而是因为它栏目少、类型严、改一笔要留痕。

世界规约就是户口本。它不负责把夕阳写得很美。它负责说清楚：有几块地、地和地怎么走、谁住哪、谁认识谁、什么条件算把事办成。美由 L3 去忙。日子由社会内核去过。本章只把账记清楚。

## 4.2 规约的栏目为什么是这些

一份 World Spec 看起来条目很多，逻辑上只有四类事实。

**空间事实。** 区域有编号、名称、类型（城镇、地牢、野外、室内、竞技场、其他）、宽高、可选 ASCII 布局、标签。传送门连接两个区域上的格子。起始区域决定玩家或观察者掉在哪。没有空间事实，社会寻路和游戏场景都无从谈起。

**主体事实。** 实体是玩家、居民、物品、摆设、敌人或触发器。居民可带身份：显示名、年龄、特质、职业、背景、家与工作区域、初始关系。日程是「某小时在某区域做某事」。背包是字符串标识列表。属性是松散但可比较的键值。主体事实决定社会内核水合出哪些人。

**结构事实。** 区域下面可以有子区域（area），子区域里有物体。物体有可变状态字符串，例如炉子是开还是关。关系是带类型与强度的有向边：认识、同盟、对手、拥有、位于、任务给予者或自定义。结构事实让感知不是「看见一个点」，而是「看见铁匠铺里的炉子」。

**因果事实。** 规则把条件映到效果。叙事持有标志位、任务和节拍。任务有状态：锁定、可接、进行、完成、失败。完成时可触发效果列表。因果事实让世界不是展览馆。

呈现提示不是第五类世界事实。它是给编译器和 L3 的便签：用二维还是三维、要不要电影层、体裁包是什么、叙事种子是观察还是通关。便签可以丢，世界仍应能被模拟。这是 SSOT 的试金石：删掉 Phaser，规约还在。

## 4.3 空间：ASCII 布局作为可检查的几何

我们不用高度图。区域的可行走性来自可选的 ASCII 布局。字符被解释成阻塞或通行。墙、水、障碍是阻塞；地板、道路、枢纽标记是通行。社会寻路在四连通网格上跑 A\*。符号模拟器里，同一区域内的日程移动不传送，跨区域才改变区域编号。

这看起来土。土有土的好处。第一，布局是文本，能进版本差分，能进大模型的上下文，能被世界算子 `reshape_layout` 整块改写。第二，门禁可以数连通分量，可以发现「房间封死」。第三，资产锻造可以从同一份字符画生成瓦片，而不另发明一套地图。

合成器按枢纽、工作、休息三种风味填字符：枢纽在中线铺路并打星号，工作区放块状建筑，休息区更封闭。这不是美学高峰，它的目标是**永远有路可走**。不可玩威胁里很大一部分，来自漂亮但不通的生成地图。

传送门采用轮毂–辐条的默认策略：新区域挂到起始区域，双向各开一门。合并世界时加前缀，避免编号撞车。空间因此是图，不是一堆孤岛。社会内核在缺门时仍允许瞬时跳转作为回落，但那是降级，应被观察为「门没铺好」。

## 4.4 条件与效果：世界的法律条文

条件是可递归的小语言。原子包括：恒真；标志位等于某布尔值；某实体属性等于某值；某实体持有某物；某实体位于某区域；某任务处于某状态。复合用与、或、非。求值相对于当前 \(W\)，没有外部隐状态。

效果同样是封闭集合：置标志、置属性、给予或剥夺物品、移动实体、开始/完成/失败任务、发出事件、推进时间。完成任务时递归执行其完成效果。这使任务成为宏观效果的打包，而不是另一套引擎。

规则在每次符号步进时检查。命中则点火并记录被触发的规则编号。事件带时间戳和载荷，供探针和日志使用。

为什么要小语言，而不是让大模型每次写一段脚本？因为脚本不可判定「这个世界还守不守法」。小语言可以穷尽测试。第 9 章的可玩性探针正是在这套语义上找：有没有任务被开始、被完成，而不是看模型是否声称完成。

法律条文有意无聊。它不描写「铁匠心情复杂地把矿石接过去」。心情是社会层的台词。法律只问：玩家背包里有没有 `iron_ore`，标志位有没有翻转。把心情写进法律，回放就会随模型温度漂移。

## 4.5 体裁如何改写同一套栏目

栏目固定，制度不固定。体裁包写在呈现提示里，缺省等于小镇。

小镇：二十四小时日周期，人口十八到二十五，三到八个区域，枢纽是广场，动词含耳语、改物体、主持集会，涌现要求二十四小时内至少七成知情。

船员：班次制时钟，人口六到十四，两到四区域，枢纽是舰桥，集会动词更弱，十二小时内五成知情即可，因为船小、班次把人错开。

修道院：仍是日周期，人口八到十八，枢纽偏食堂或礼拜堂，十八小时六成知情。日课替代晚会，但内核算法不变。

时钟格式化必须跟包走。值班世界若显示「凌晨三点」，是一次典型的塌模板，只是塌在文案上。实现里，值班显示「第几轮第几班」，事件钟显示「时点」。这是小事，用户一眼能看出你有没有把制度当真。

## 4.6 世界算子：改建许可证

若每次修改都让模型重写整份 JSON，谱系不存在，差分不可读，资产重绘范围也不知道。世界算子把修改限制成有限动词。

空间类：增加区域、扩展区域、编辑区域、重塑布局。增加区域时自动试图挂上双向门。

主体类：增加、编辑、删除实体；编辑对白种子。

叙事类：置标志、置事实、增加任务。

制度类：设置体裁包、设置时钟。

结构类：合并另一个世界，并加编号前缀。

每次成功应用：版本号加一；生成修订记录（父版本、算子、摘要、时间）；计算脏资产键。失败则返回问题列表，世界不变。这个「不变」和数据库事务是同一类道德：部分成功比失败更可怕，因为它留下无法命名的中间态。

飞行员智能体倾向发出编辑实体、置标志这类角色向算子。导演智能体倾向增加区域、增加事件摆设。他们都可以调用大模型起草算子，也可以走启发式。无论谁起草，入口只有 `Apply`。这是不变量 5 的实现。

多轮聊天编辑走 `planWorldOps`：把用户的「再加一个厨子」变成算子列表。若请求看起来很重，映射出的算子却空，结果标记为未理解，而不是标记为成功的空操作。空成功是产品谎言。

## 4.7 谱系、差分与记忆

平台把世界头和修订写入数据库。恢复历史版本等于把某次修订的 \(W\) 重新当作尖端。差分函数比较两份规约，供门禁判断「这一编辑是否暗中换了体裁或掏空了人口」。

项目级世界记忆（事实、情节、对话、任务）不是居民记忆流。它是给后续规划提示词用的瘦上下文，避免把整份聊天记录塞给代码或规划模型。从规约抽取事实，再按查询检索，是同一 SSOT 的衍生视图。衍生视图可以丢，户口本不行。

居民记忆流属于第 6 章。这里只需画界：一个记世界，一个记某个人的日子。混用会导致「全镇共用一个大脑」或「规划器只能看见某个人的八卦」。

## 4.8 校验：先当坏人，再接受世界

解析器用 Zod 填默认值并拒绝类型错误。校验器继续做引用检查：起始区域必须存在；实体必须落在已知区域；传送门两端必须存在；任务和规则引用的标识必须能解析。软修复发生在大模型草稿上：补标识、补版本、丢掉指向不存在区域的门、把标题截到可显示长度。软修复的目标是**不因一次字段缺失丢掉整份有用的草稿**，而不是默默改掉用户承诺。

承诺检查不在纯结构校验里，而在质量门禁里。原因是：结构正确的斯坦福小镇，对「运河货船」仍是幻觉。结构校验回答「像不像一份世界」；承诺检查回答「像不像这一份世界」。

## 4.9 规约如何被呈现，却不被呈现占有

浏览器里的世界游戏引擎读取 `public/world.json`。标题、探索、战斗、结局是场景，不是另一份真相。探索场景根据实体种类决定能否对话、拾取、战斗。时间键推进规约时钟。任务日志读叙事栏目。

这意味着美术可以全换，键位可以全换，只要引擎按同一解释器执行效果，世界仍是同一个。反过来，若程序员在场景里写死「走到这里就算任务完成」，而规约里没有对应效果，SSOT 就被破坏。代码评审应当把这种写法当成缺陷，而不是当成快捷方式。

三维呈现与二维呈现共享规约。切换三维不得生成一套新的任务。LingBot 的区域影片挂在呈现提示的 `spatialAssets` 上，按区域切换。影片缺失时探索仍继续。第 7 章展开视觉边界；本章只需锁定：呈现提示可以指向影片，影片不能回写任务。

## 4.10 与角色扮演填充的边界

社会优先的世界可以没有任务、没有敌人。角色扮演提示则要求压力：至少若干任务、至少某种对抗。深度填充模块在两种模式下做不同的补：社会模式补人和区域，不补狼；角色扮演模式补任务和敌人。填充物仍必须通过校验，仍不得使用禁止标识。

叛徒一类关键词可以在启发式合成里改某个居民的个性和对白种子，把它变成叙事事实，而不是改游戏规则引擎。这是一个有意的选择：社会观察模式下，「叛徒」首先是人设和谣言的种子，不是自动出现的战斗标签。若用户同时要战斗循环，再由规则与敌人实体承接。

## 4.11 条件求值的几个容易错的地方

标志位缺省为假。问「标志是否等于真」在从未设置时得到假，这是安全的悲观。问「标志是否等于假」在从未设置时得到真，作者必须知道自己在问什么。属性比较是严格相等，字符串和数字不会偷偷互转，避免「hp 为 3」和「hp 为 "3"」变成两个世界。背包检查是成员关系，不计数，两个铁矿和一个铁矿在法律上常常无区别——若要计数，应把数量写成属性或把物品写成带堆叠的结构。当前实现选择简单，角色扮演取矿任务因此通常是「持有即可」，不是「持有三块」。

与或非的短路可以按普通逻辑理解。非把求值翻转。循环引用在模式上不出现，因为条件树是无共享的值对象。规则之间的顺序是数组顺序。同一拍内一条规则的效果可能让后一条规则的条件变为真，是否允许「链式点火」取决于模拟器是否在同一 tick 里重复扫描。实现选择应写进测试：否则「我设置了标志，为什么同一步任务没完成」会变成玄学。产品上，宁可明确「下一拍再生效」，也不要隐式连锁到难以回放。

## 4.12 修订谱系像 git，但不等于 git

把世界放进 git 也能差分。为什么还要世界算子？因为 git 差分的是文本，算子差分的是意图。一次「加区域」在 JSON 里可能显示为几十行数组插入，在谱系里是一条带脏资产键的合法改建。恢复历史版本时，你恢复的是经过校验的世界，而不是可能半残的手改 JSON。合并世界时的前缀策略，相当于命名空间，避免两座镇的 `npc_smith` 互殴。

谱系仍可以导出到 git。二者互补：git 管文件，算子管语义。平台数据库是语义的权威存储，工作区文件是呈现的工作拷贝。若有人只改工作区里的 `world.json` 而不走算子，下一次生成任务可能覆盖他的暗改。这是痛苦的，也是正确的：暗改不可回放。

## 4.13 把货船例子写成栏目

空间：区域 `bridge`、`hold`、`sleep_bay`，也许还有 `galley`。门连接舰桥与货舱、货舱与休眠舱。起始在舰桥。ASCII 让走廊可走。

主体：八名船员，职业覆盖值班官、水手、厨子、机工等。家在休眠舱铺位，工作在舰桥或货舱。日程按班次，而不是按农闲。

结构：舰桥上有舵轮物体，休眠舱有铺位物体。关系含同班与上下级。

因果：观察世界可以没有任务。可以有一条规则：若某标志「警报」为真，则若干人的属性「值班」为真。警报由导演算子或耳语间接引起，不由视频帧引起。

呈现：体裁包船员，叙事种子观察，电影层默认关。

若任何一栏被小镇模板填满，合同失败。栏目表是检查清单，不是散文大纲。

## 4.14 条件语言为什么保持「无聊」

每过几年都会有人提议：让条件直接写自然语言，「如果铁匠高兴并且玩家看起来可信就给钥匙」。这在演示里很动人。在回放里会变成灾难。高兴是连续的、语境的、模型相关的。钥匙交接是会计事件。会计事件必须在十年后用同一份日志重放得到同一结果。无聊的条件语言是对时间的尊重。

若确实需要「高兴」，正确接法是：社会层把高兴写成属性或标志，由一次合法效果置位，条件再去读这个离散位。模型可以建议置位，不能在条件求值时被现场询问。现场询问会把法律变成座谈会。

效果集合同样应保持关闭。每增加一种效果，模拟器、探针、编译器、呈现引擎都要认识它。开放效果等于把 SSOT 的门重新打开。想要新效果，先走版本化的规约演进，而不是在某次提示词里发明。

## 4.15 关系边不是社交网络产品

关系类型少而硬：认识、同盟、对手、拥有、位于、任务给予者、自定义。强度在 -1 到 1。它不够用来推荐好友，够用来让社会内核知道该找谁说话，够用来让评测数出新边。把知识图谱那一套实体链接全部搬进来，会让规约重得无法进模型上下文。需要更细的社会关系时，社会状态里的 `SocietyRelation` 可以比规约更密，规约只存初始种子。运行时变密、规约保持稀，是又一次分层。

## 4.16 小结

世界规约把空间、主体、结构、因果写成可校验的栏目；世界算子把修改写成可记录的许可证；模拟器把法律写成确定性的火。有了账本，才能谈合同（第 5 章）和日子（第 6 章）。没有账本的智能体，只是在别人家里即兴演出。法律必须无聊，改建必须留痕，呈现必须可缺席。这三句比任何示意图都更接近 SSOT 的可操作定义。
